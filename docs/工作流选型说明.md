# 康伴数字人主对话工作流选型说明

> 依据：`docs/02_技术规范.md` 第五章「总体架构」、第十章「接口与技术栈映射」。
> 结论：主对话链路按 **Agent 类型**建设，采用“规则层 + 本地 Laya S1 + LangGraph Supervisor + 五个专业子 Agent”的受约束多 Agent 编排；规则层、用药、健康告警等确定性强的子流程内部按 **Workflow** 实现。

## 一、目标用户

| 角色 | 用户画像 | 入口 | 核心诉求 | 权限边界 |
| --- | --- | --- | --- | --- |
| 长者 | 社区住户，主要使用者；可能听力、视力、表达或操作能力下降 | 卧室平板、语音、WebRTC | 低门槛对话、情感陪伴、用药提醒、健康采集、戏曲/影视、生活信息 | 本人语音/记忆全量；健康记录可读并可语音播报；可申请删除声纹/记忆；可自动生成工单 |
| 同房间其他长者 | 与长者同住，可能临时进入对话范围 | 现场语音、同一设备 | 正常交流；不暴露室友隐私 | 个性化对话需隐私收敛，隐藏敏感内容；仅可发起与自身相关的工单 |
| 护工 | 社区照护人员，移动端/工作站 | 工作站、移动端、工单 | 查看负责长者的健康与用药、处理提醒和异常 | 工作模式下可访问负责长者的个性化对话；可修改用药计划（二次确认）；可创建/处理工单；退房流程中可申请删除声纹/记忆 |
| 医生 | 社区医生/签约医生 | 工作站、HIS mock | 查看完整健康记录、调整用药、处理升级事件 | 健康记录完整可读；可修改用药计划；可创建工单；不直接操作长者人设 |
| 子女家属 | 长者家属，远程关心 | 最简 H5 | 了解日报摘要、接收异常通知 | 仅日报摘要；不可读原始健康数据、不可读完整对话；不替代 SOS |
| 运营管理员 | 社区运营/内容与配置人员 | 管理端 | 配置人设形象、审计权限操作、维护内容库 | 可配置人设形象；删除声纹/记忆属于审计类操作；不参与临床判断 |
| 未登记访客 | 临时到访人员 | 现场语音 | 基础问答；不得获取住户数据 | 无身份即拒绝个性化数据；敏感请求转护工 HITL |

身份判定顺序固定为：设备 JWT → 长者/护工人脸或声纹 → 会话上下文 → 运行时 `runtime_context`。身份只从 token 与 `runtime_context` 读取，不接受请求体自报 `elder_id`。

## 二、核心流程

### 2.1 主链路

```text
N1 触发
  长者语音 / 平板点击 / 定时任务（用药、健康采集、主动关怀）
    ↓
N2 接入与鉴权
  WebRTC 信令或 HTTP/SSE → 设备 JWT → 会话建立 → 生成 trace_id
    ↓
N3 身份与场景
  长者 / 护工 / 医生 / 家属 / 管理员 / 访客 → 权限与隐私策略
    ↓
N4 上下文注入
  elder_id、persona、room、device、thread_id、记忆摘要、当前场景
    ↓
N5 流式 ASR
  语音转文本 + 置信度；失败 → 文字模式 + 护工工单
    ↓
N6 规则层（前置）
  关键词/正则/状态机：紧急词、敏感词、确定性设备指令、时段规则
  命中 → 直接返回或转 HITL，不调用模型
    ↓
N7 本地 Laya S1
  7 类意图、敏感判断、是否升级、隐私收敛
  置信度 ≥0.85 → 直接闭环；<0.85 或 Laya 失败 → S2
    ↓
N8 S2 Supervisor
  DeepSeek / Qwen：开放域对话、任务分解、Tool 编排、人设与记忆
    ↓
N9 专业子 Agent
  陪伴对话 / 健康 / 用药 / 娱乐 / 信息与工单
    ↓
N10 Tool 与 MCP
  天气、工单、微信等白名单工具；身份取 runtime_context.elder_id；每轮 ≤8 次
    ↓
N11 HITL 与输出
  敏感意图、漏服升级、健康告警、用药变更 → 人工确认
  通过后流式 TTS + viseme 口型驱动 + SSE/WebRTC 回传
    ↓
N12 观测与沉淀
  trace_id 贯穿日志；decision_logs、会话摘要、记忆写入、评测采样
```

### 2.2 分支与降级

| 分支 | 触发条件 | 处理 |
| --- | --- | --- |
| 规则直返 | 紧急词、敏感词、确定性设备指令 | 不调模型；敏感/急症转护工 HITL，急症只告警不引导急救 |
| S1 闭环 | 意图置信度 ≥0.85 且无高危副作用 | 本地 Laya 输出话术/动作，直接 TTS |
| S1 升级 | 置信度 <0.85、开放域问题、需要多步工具 | 进入 S2 Supervisor |
| Laya 不可用 | 本地模型加载/推理失败 | 全量降级 S2；记录降级原因与延迟 |
| ASR 不可用 | 流式识别超时/失败 | 切换文字模式，创建护工工单 |
| TTS 不可用 | 合成超时/失败 | 文字模式 + 护工工单；不阻塞对话状态 |
| S2 超时/限流 | 第三方 API 异常 | 重试 1 次；仍失败用预设话术兜底并记录 |
| 身份不足 | 访客、跨房间、家属越权 | 隐私收敛或拒绝；敏感请求转 HITL |
| 高危副作用 | 用药变更、漏服升级、健康告警、敏感意图 | 必须 HITL 确认后才执行 |
| 工具超预算 | 单轮 Tool 调用将超过 8 次 | 停止扩展，返回当前结果并转人工 |

### 2.3 关键节点约束

- N2 必须生成并透传 `trace_id`；Agent 链路必须带 `thread_id`。
- N4 的 `elder_id` 只来自 token / `runtime_context`，不信任请求体。
- N7 的敏感判断宁可错杀；命中即一票否决并写 `decision_logs`。
- N10 的 Tool 调用必须校验 `elder_id`，MCP 只暴露白名单工具并留审计日志。
- N11 的高危副作用不得由模型直接执行，必须人工确认。

## 三、技术栈

| 环节 | 选型 | 说明 |
| --- | --- | --- |
| 接入与 API | Python 3.10+、FastAPI、uvicorn、SSE、WebRTC 信令 | HTTP/SSE 与实时语音统一后端；uvicorn 作为 ASGI 运行入口 |
| 实时语音 | aiortc、第三方流式 ASR/TTS | 全双工语音；ASR 带置信度，TTS 带 viseme 时间轴 |
| 配置 | Pydantic v2 + Pydantic Settings | 从项目根目录 `.env` 加载；密钥只走环境变量，`SecretStr` 不落日志 |
| 规则层 | Python 正则/关键词/状态机 | 确定性、低延迟、可测试；不引入模型 |
| S1 快决策 | 本地 Laya `convaiinnovations/laya`（`subfolder=multilingual`） | 本地 CPU 推理；P95 目标 ≤200ms；置信度阈值 0.85 |
| S2 开放域 | DeepSeek / Qwen | 第三方 API；超时/限流重试 1 次，失败预设话术兜底 |
| 编排 | LangGraph Supervisor + 五个专业子 Agent | 有状态图、条件边、检查点；按职责拆分，避免单 Prompt 全能 Agent |
| Tool 调用 | Tool Calling + MCP（weather / workorder / wechat） | 白名单、身份注入、≤8 次/轮、审计日志 |
| 记忆 | PostgreSQL + pgvector | 查询必须带 `elder_id`；敏感内容隐私收敛 |
| 数据层 | SQLAlchemy 2.x + Alembic | 声明式 ORM；schema 只走迁移，不手改库 |
| 会话与缓存 | Redis | 会话状态、限流、短期上下文；不存完整病历/原始录音 |
| 定时任务 | APScheduler | 用药提醒、健康采集、主动关怀；与请求链路解耦 |
| 观测 | 结构化 JSON 日志 + trace_id、Langfuse、eval_gate | 每行日志带 trace_id；评测门禁未过不得推送 |
| 部署 | Docker Compose、pytest | 本机 pg/redis/backend/frontend/Laya/MCP；禁止生产库 |

## 四、禁区

### 4.1 架构与编排禁区

- 禁止把主对话做成纯固定 Workflow：开放域表达、上下文追问、工具组合无法穷举。
- 禁止把主对话做成无约束的全能 Agent：身份、权限、工具预算、HITL 必须由外部代码约束。
- 禁止让模型决定 `elder_id`、角色权限或 Tool 白名单；身份只认 token / `runtime_context`。
- 禁止缺少三道闸门：会话闸门（伪造 `thread_id` 返回 403）、记忆闸门（pgvector 查询必须带 `elder_id`）、工具闸门（身份只认 `runtime_context`）。
- 禁止单轮 Tool 调用超过 8 次，禁止无上限 ReAct 循环。
- 禁止高危副作用自动执行：敏感意图、漏服升级、健康告警、用药变更必须 HITL。

### 4.2 技术与合规禁区

- 禁止把 System One 放到云端或第三方推理 API；B5 要求本地 Laya。
- 禁止医疗诊断结论、替代 SOS 或急救；B1/B2 只记录、提醒、告警并建议问医生。
- 禁止存完整病历或原始录音；B8 只存结构化摘要，音频中间态 72h TTL。
- 禁止未授权曲库/影库、AI 歌曲生成/演唱；B4/B6 仅教学模拟、已授权或公有领域素材。
- 禁止接入物业/支付/门禁系统；B7 外部依赖仅微信/HIS mock。
- 禁止移动端原生 App、多租户、diarization、高精度 3D 建模/动捕；B3/B9/B10/B11。
- 禁止硬编码 key / 口令 / token；禁止连接生产数据库；禁止暴露 DB/Redis 到公网。
- 禁止日志落身份证号、具体剂量或明文密钥；日志每行必须带 `trace_id`。

## 五、验收方式

| 验收项 | 判据 | 验证方式 |
| --- | --- | --- |
| 端到端时延 | P95 ≤1.5s | 语音/文字混合回放压测，按 trace_id 统计 |
| S1 时延 | P95 ≤200ms（目标） | 本地 Laya 单问/四判断基准；当前四判断 P50 223ms 未达标，改问题集/路由后复测 |
| S1 准确率 | 意图准确率 ≥90% | 50 条标注集，混淆矩阵 |
| 敏感召回 | ≥95% | 50 条标注集，漏判逐条复盘 |
| S1 闭环率 | ≥60% | 生产/仿真会话采样，统计未升级 S2 比例 |
| 身份准确率 | 单人 ≥99%，双人 ≥90% | 声纹 + 人脸/设备多模态测试集 |
| 工具预算 | 单会话 ≤8 次 | trace 级 Tool 调用计数与越权用例 |
| 三道闸门 | 全部通过 | 伪造 thread_id 403、跨 elder_id 记忆查询拒绝、Tool 身份伪造拒绝 |
| HITL | 高危副作用 100% 人工确认 | 注入敏感/漏服/健康告警/用药变更用例 |
| 降级 | ASR/TTS/Laya/S2 故障均可解释 | 故障注入，验证文字模式、S2 兜底、预设话术、工单 |
| 可观测性 | 每行日志含 trace_id；链路可检索 | 发起请求后检查日志与 `X-Trace-ID` 响应头 |
| 评测门禁 | `python eval/eval_gate.py` 通过 | pre-push 同入口执行 |
| 角色矩阵 | 五类角色越权用例全部拒绝/收敛 | pytest 接口与权限用例 |

## 六、类型判定

**结论：主对话工作流属于 Agent 类型，具体形态是“受约束的多 Agent 编排”，不是纯 Workflow，也不是无约束的自由 Agent。**

判定依据：

1. **输入开放**：长者表达、口音、上下文指代和情绪状态无法用固定分支穷举，纯 Workflow 会产生大量不可维护的分支。
2. **路径动态**：是否需要 ASR、是否命中规则、S1 是否升级、调用哪些 Tool、是否需要 HITL，均由运行时状态决定。
3. **有状态与记忆**：需要 `thread_id`、会话历史、长者画像与 pgvector 记忆，跨轮次保持上下文。
4. **工具编排**：天气、工单、微信等工具需要按目标组合调用，并受身份、权限和预算约束。
5. **必须有确定性护栏**：规则层、敏感判断、身份闸门、Tool 白名单、HITL 和 ≤8 次预算由代码强制执行，不能交给模型自由决定。

因此：

- **整体**：Agent（LangGraph Supervisor + 五个专业子 Agent）。
- **确定性强的子流程**：Workflow。规则层是代码状态机；用药提醒、健康采集、漏服升级、健康告警按固定步骤和固定判据执行；这些子图可以是 Agent 内部被调用的受约束 Workflow。
- **边界**：Agent 负责“理解与编排”，Workflow 负责“合规与可重复执行”，两者组合，而不是二选一。
