# 「康伴」3D 数字人康养陪伴系统 · TDD 用例设计

> 版本：v1.0 ｜ 阶段：4/7 ｜ 上游输入：`01_PRD`（功能/边界）+ `02_技术规范`（架构/闸门/性能）+ `03_安全审计`（威胁/控制点）
> 本文档定义**如何证明做对了**：测试金字塔、单元/接口/闸门/注入用例、评测集与门禁。

## 一、文档定位与目的

以"测试先行"原则，把需求、技术规范与安全审计的每一条可验证结论转化为**可执行的用例**。用例是阶段 5 PoC 与阶段 6 实施的验收依据，也是阶段 7 验收的客观判据。

## 四、业务边界约束（B1–B11 的测试落点）

| 边界 | 对应测试用例 |
| --- | --- |
| B1 不做医疗诊断 | 健康 Agent 输出断言：不含诊断结论；异常话术为"建议问医生" |
| B2 不替代 SOS | 急症命中仅触发告警，无急救引导话术 |
| B4 不做 AI 歌曲生成 | 依赖/模块清单断言：无生成/演唱模型 |
| B5 不依赖商业 Jev API | System One 为本地推理；出站请求断言不含第三方推理 API 敏感文本 |
| B6 不做盗版曲库/影库 | `media_library` 全量 `copyright_status` 合规；无爬取模块 |
| B7 不接物业系统 | 外部依赖白名单断言（仅微信/HIS mock） |
| B8 不存完整病历/原始录音 | 表结构无违例字段；音频 72h TTL 删除任务测试 |
| B9 不做原生 App | 家属端为无框架 H5 |
| B10 不做多租户 | 无 tenant 抽象字段/接口 |
| B11 不做 diarization | 重叠语音触发"谁在说话"澄清话术（无分离输出） |

## 五、测试金字塔与覆盖率门槛

```
         /\
        /  \  E2E 场景评测集（20 固定场景 + 演示视频脚本）

```

## 十、20 固定长者场景评测集 + 50 条 Laya 标注集

- **20 场景评测集**：覆盖五类职责（陪聊/用药/健康/娱乐/信息）+ 边界场景（敏感急症、隐私收敛、域外澄清）。输出 `eval/reports/v1_baseline.md`：任务成功率、P95 延迟、S1 闭环率、分层命中率、单会话 token 成本、敏感召回率、工具调用准确率、人工接管率。
- **50 条 Laya 标注集**：覆盖 7 类意图（闲聊/用药查询/戏曲点播/电影点播/天气查询/健康采集/其他，娱乐点播为层次化标签）+ 敏感 + 域外 + 隐私收敛。用于意图准确率（≥90%）与敏感召回率（≥95%）测量。
- **bad case 回流**：每个失败 case 标注归因层（ASR/Laya/召回/LLM/Tool/编排）。

## 十一、eval_gate 门禁

`eval_gate.py`：批量跑评测集 + 断言阈值，接入 git pre-push hook（本地 CI 门禁），未达标阻断推送。
